# Table Booker: контекст переноса для нового чата

Состояние на 2 октября 2026 года, около 13:31 МСК. Этот файл относится к отдельному приложению; текущий открытый репозиторий gustaw-fin не является подтверждённым репозиторием Table Booker.

## Задача пользователя

Перенести уже развёрнутое приложение Table Booker со старого, скомпрометированного VPS на новый чистый VPS. Выяснить, где находятся исходники, база данных и необходимые файлы; подготовить новый деплой, перенести данные и переключить домен table-booker.ru. На старом VPS есть другие приложения: сначала провести инвентаризацию, не удалять их и не останавливать весь сервер. Пользователь хочет продолжить этот перенос в новом чате. Покупать второй VPS не нужно.

Домен на скриншоте панели Timeweb: table-booker.ru, оплачен до 17 апреля 2027, показана привязка к сервису tapir. Реальные A/AAAA/CNAME и текущий HTTPS перед переключением ещё не проверены. Срок регистрации домена не является сроком SSL-сертификата.

## Ограничения доступности, которые нельзя потерять при переносе

gustaw.ru периодически недоступен с iPhone Wi-Fi/мобильная сеть и Mac с VPN/без него. Во время подтверждённых отказов TCP соединение устанавливается, а TLS ClientHello отсутствует на eth0 VPS либо приходит только первым сегментом. Локальный HTTPS одновременно возвращает 200. Конкретный узел/оператор потери не установлен; Timeweb, VPN или ТСПУ не объявлены доказанной причиной.

Уже проверены без устойчивого исправления: TLS 1.2/1.3, MSS 1200, ECN, offload, внешний порт 8443, сегментация ClientHello. SSH-туннель ранее давал 20/20 успешных запросов при отказе прямого пути. Не повторять весь этот набор и не перезапускать Nginx/Next.js ради временного восстановления.

Временное TCPMSS правило удалено, relay 8443 остановлен, тестовое разрешение UFW 8443 удалено. Пользователь вернул GRO/GSO/TSO в on; tcp_ecn=2. HTTP/2 оставлен включённым. После включения h2 один внешний TLS timeout повторился, затем пользователь подтвердил работу страниц, фотографий, логинов и лайков во всех опробованных вариантах. Устойчивость не доказана.

Последние присланные журналы подтверждают успешные HTTP/2 запросы iPhone и работу OAuth/ресурсов; access log не видит соединения, не дошедшие до HTTP. tail -f только наблюдает журнал, его можно остановить Ctrl+C, на сайт это не влияет.

Актуальный план доступности: /Users/tapir/Programming/gustaw-fin/SITE_AVAILABILITY_NEXT_STEPS.md. История: NETWORK_DIAGNOSIS.md и SITE_AVAILABILITY_HANDOFF.md в том же каталоге. OPTIMIZATION_ROADMAP.md относится к отдельной уже выполненной работе над gustaw, а не к Table Booker.

## Порядок работы нового чата

1. Найти правильный локальный репозиторий Table Booker и прочитать его AGENTS.md/инструкции. Проверить стек и способ деплоя; они пока неизвестны.
2. Провести read-only инвентаризацию старого VPS: конфигурация домена Nginx, процессы/службы/контейнеры, каталоги проекта, подключения и тип БД, uploads/volumes, задачи обслуживания. Не выводить значения секретов; фиксировать названия и расположение. Выяснить, есть ли актуальные записи пользователей и нужна ли согласованная пауза записи на время окончательного переноса.
3. Проверить новый VPS и подобрать свободный upstream порт; подготовить точный план файлов, сервиса, БД, дисковых ресурсов и отката. Перед изменениями коротко сообщать, что меняется и зачем. Не устанавливать тип БД по догадке: PostgreSQL/MySQL/SQLite/внешний сервис ещё не выяснены.
4. Сделать проверенный экспорт нужной БД и файлов, развернуть приложение из проверенных исходников с новыми необходимыми секретами. Не оставлять единственную копию данных на старом сервере.
5. До переключения DNS проверить приложение на новом VPS и нужный виртуальный хост. Для HTTPS использовать домен/SNI и проверку сертификата; --resolve позволяет проверять адрес без изменения публичной DNS зоны. Проверить логин, запись данных, uploads и остальные функции, которые реально есть у Table Booker.
6. Зафиксировать прежние записи и TTL, подготовить откат, затем переключить только нужные записи table-booker.ru/www, учитывая AAAA. Получить/проверить сертификат и способ автопродления; не переносить TLS ключ со скомпрометированного сервера. Не менять DNS gustaw.ru.
7. Проверить Table Booker и gustaw.ru рядом на одном устройстве/маршруте через HTTPS: iPhone Wi-Fi/мобильная сеть, VPN по возможности фиксировать; Mac VPN сохранять для общения. Сравнение HTTP приложения с HTTPS не локализует TLS проблему. Другой домен/приложение — дополнительный контроль, не строгий тест только IP.
8. Зафиксировать итог переноса, фактические каталоги/порты/службы/БД, DNS и сертификат, результаты доступности, незавершённые шаги. Пользователь передаст итог в диагностический чат; автоматически чаты контекстом не обмениваются.

## Стиль и критерий завершения

Пользователь устал от недели повторяющихся проверок и хочет вернуться к разработке личного журнала путешествий. Объяснять коротко и простыми словами, не покупать инфраструктуру, не просить повторно разрешать обычные действия в рамках переноса. Одна успешная загрузка не подтверждает стабильность: ориентир диагностики — минимум 20 новых HTTPS соединений на каждую целевую комбинацию и повтор позже, отдельно проверять функции приложения. Перенос Table Booker и установление причины сетевого сбоя — отдельные результаты.

На момент передачи подключение к старому VPS и инвентаризация Table Booker в этом чате не выполнялись; БД, репозиторий, runtime, сервис и текущий DNS неизвестны. Это контекст и план, а не отчёт об уже выполненном переносе.
