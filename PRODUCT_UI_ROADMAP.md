# Product roadmap: визуальная система Gustaw

## Зачем нужен этот документ

Этот roadmap фиксирует согласованное направление развития интерфейса Gustaw.
Он не заменяет `PRODUCT_BACKLOG.md`: backlog хранит отдельные функциональные и
UX-задачи, а здесь описаны порядок визуальной переработки, критерии готовности и
контрольные точки.

Техническая оптимизация продолжает вестись отдельно в
`OPTIMIZATION_ROADMAP.md`.

## Принцип работы

Интерфейс обновляется короткими итерациями, по одному экрану или компоненту.
После каждой итерации владелец продукта проверяет результат локально и отмечает,
что нужно изменить. Следующий этап не должен начинаться, пока текущий визуально
не принят.

Для каждого этапа используется один и тот же цикл:

1. Согласовать референс и поведение.
2. Реализовать экран или компонент без изменения бизнес-логики.
3. Проверить desktop, tablet и mobile.
4. Получить визуальную обратную связь.
5. Внести точечные исправления.
6. Зафиксировать принятый вариант и перейти дальше.

## Согласованное визуальное направление

- Космический фон в чёрно-коричневой гамме с золотыми акцентами.
- Полупрозрачные тёмные панели с мягким локальным свечением.
- Тонкие золотые границы без тяжёлых теней и лишнего блеска.
- Крупный редакционный serif используется только для главных заголовков.
- Элементы управления используют читаемый sans-serif.
- Небольшие служебные заголовки набираются прописными буквами с умеренной
  разрядкой.
- Основное действие может иметь золотую заливку; вторичные действия остаются
  контурными.
- Hover не должен сдвигать контейнеры или менять размеры интерфейса.
- Сгенерированные изображения являются дизайн-референсами. Сам интерфейс
  реализуется HTML и CSS, а не вставкой цельного изображения.

## Готовые референсы

- `AUTH_DESIGN_REFERENCE.png` — вход и регистрация.
- `BOOKING_DESIGN_REFERENCE_FINAL.png` — выбор даты аудиенции.

Черновые изображения сохраняются только для сравнения. При реализации следует
ориентироваться на варианты, явно помеченные как финальные или одобренные.

## Этап 1. Основа дизайн-системы

**Статус:** техническая основа реализована, требуется визуальная проверка.

### Задачи

- [x] Зафиксировать основные цвета фона, текста, границ и состояний.
- [x] Зафиксировать два семейства типографики: editorial serif и интерфейсный
  sans-serif.
- [x] Определить стандартные радиусы панелей, полей и кнопок.
- [x] Определить размеры основных, вторичных и компактных кнопок.
- [x] Создать повторно используемые стили панели, золотой кнопки и контурной
  кнопки.
- [x] Определить hover, active, focus-visible и disabled без сдвигов элементов.
- [ ] Проверить контраст текста и видимость клавиатурного фокуса.

### Первый кадр и загрузка

- [x] Установить тёмный фон `html` и `body` до загрузки космического изображения.
- [x] Установить тёмный `theme-color` и `color-scheme`.
- [x] Добавить тёмную непрозрачную подложку Hero.
- [x] Привести scrollbar к тёмной палитре приложения.
- [ ] Визуально проверить первый кадр при отключённом кэше и медленной сети.

### Критерии готовности

- Одни и те же значения не копируются вручную между несколькими экранами без
  необходимости.
- Компоненты имеют предсказуемые размеры и состояния.
- Изменение общей кнопки или панели можно сделать централизованно.

## Этап 2. Вход и регистрация

**Статус:** визуальная итерация принята 2 октября 2026 года.

### Задачи

- [x] Довести двухколоночную desktop-композицию по auth-референсу.
- [x] Оставить функциональную кнопку «На главную» в верхней области панели.
- [x] Проверить вертикальную композицию на мобильном экране.
- [x] Сохранить постоянную высоту формы при появлении и исчезновении кнопки
  выхода.
- [ ] Проверить длинные сообщения об ошибках и состояния загрузки.
- [x] Не менять работающую логику входа, регистрации, OAuth и показа пароля.

### Критерии готовности

- Страница соответствует принятому референсу на широком экране.
- На телефоне нет горизонтального скролла и наложений.
- Форма не дёргается при выходе, ошибке или повторном входе.

## Этап 3. Страница аудиенции

**Статус:** первая визуальная итерация реализована, требуется проверка владельца
продукта на desktop и mobile.

### Задачи

- [x] Собрать единую широкую панель по
  `BOOKING_DESIGN_REFERENCE_FINAL.png`.
- [x] Перенести описание, цену, длительность и телефон в левую колонку.
- [x] Использовать формулировку: «Выберите день и свободный час, чтобы
  официально погладить Густава».
- [x] Разместить календарный сценарий в правой колонке.
- [x] Сделать выбранную дату визуально заметной золотой заливкой.
- [x] После выбора даты показывать свободное время в той же рабочей области.
- [x] Добавить этап подтверждения без резкой смены визуального языка.
- [x] Встроить кнопку возврата в композицию панели.
- [x] Продумать состояния: загрузка, нет свободного времени, ошибка и успешная
  запись.

### Критерии готовности

- Пользователь понимает последовательность «дата → время → подтверждение».
- Смена этапов не вызывает скачков всей страницы.
- Все реальные данные и текущая логика записи сохранены.

## Этап 4. Административная кнопка загрузки

**Статус:** направление согласовано, дизайн не реализован.

### Задачи

- [ ] Заменить синюю кнопку `Upload` на элемент общей дизайн-системы.
- [ ] Выбрать финальную подпись: «Добавить фото» или «Загрузить фото».
- [ ] Использовать золотой контур, тёмный фон и линейную иконку загрузки.
- [ ] Сделать область нажатия не меньше 44 × 44 px.
- [ ] Добавить hover и focus без изменения геометрии кнопки.
- [ ] Сохранить видимость элемента только для администратора.

### Критерии готовности

- Кнопка не выглядит элементом стороннего интерфейса.
- Её назначение понятно без знания английского языка.
- Роль и существующая логика загрузки не изменены.

## Этап 5. Общие элементы главной страницы

- [ ] Привести основные CTA к общей системе приоритетов.
- [ ] Проверить плашку лайка: кликабельна вся область, но анимируется только
  сердце.
- [ ] Унифицировать интервалы, границы и состояния карточек.
- [ ] Проверить, что декоративные эффекты не ухудшают читаемость фотографий.

## Этап 6. Адаптивность и доступность

- [ ] Проверить ширины 320, 375, 768, 1024 и 1440 px.
- [ ] Проверить управление клавиатурой и видимый focus-visible.
- [ ] Проверить кликабельные области не меньше 44 × 44 px.
- [ ] Проверить `prefers-reduced-motion`.
- [ ] Проверить контраст основных и вторичных текстов.
- [ ] Убедиться, что декоративный фон не блокирует взаимодействие.

## Этап 7. Финальная проверка и выпуск

- [ ] Выполнить production-сборку.
- [ ] Проверить вход, регистрацию, Google OAuth и GitHub OAuth.
- [ ] Проверить роль администратора и загрузку фотографий.
- [ ] Проверить лайки и запись на аудиенцию.
- [ ] Проверить social preview с новым изображением v3.
- [ ] Задеплоить на VPS с возможностью отката.
- [ ] Выполнить smoke-тест через Next.js, Nginx и публичный домен.

## Что не входит в визуальный roadmap

- Изменение схемы базы данных без отдельной функциональной задачи.
- Переработка OAuth и ролей, если текущая логика работает.
- Генерация множества фоновых картинок без подтверждённой необходимости.
- Замена настоящего интерфейса цельными сгенерированными изображениями.
- Одновременная переработка всех экранов без промежуточной проверки.

## Ближайшее действие

Визуально проверить первую реализацию этапа 3 на desktop и mobile, внести
точечные исправления и после принятия перейти к административной кнопке
загрузки.
