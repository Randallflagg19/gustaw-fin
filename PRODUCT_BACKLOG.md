# Product backlog Gustaw

Этот файл хранит функциональные и UX-улучшения приложения. Задачи по
производительности ведутся отдельно в `OPTIMIZATION_ROADMAP.md`, а проблемы
внешней доступности — в `SITE_AVAILABILITY_HANDOFF.md`.

Последовательная визуальная переработка интерфейса ведётся в
`PRODUCT_UI_ROADMAP.md`.

## Авторизация и аккаунт

### Поведение формы входа

- [x] После выхода из аккаунта на странице `/sign-in` оставлять пользователя на
  этой же странице и показывать форму входа. Не перенаправлять его на главную.
- [x] После успешного входа перенаправлять пользователя с `/sign-in` на главную
  страницу `/`. Это текущее желаемое поведение.
- [x] При неправильном пароле сохранять введённый логин в поле формы. Пользователь
  должен исправить только пароль, а не вводить логин повторно.
- [x] Отправлять заполненную форму входа по клавише Enter как из поля логина, так
  и из поля пароля.
- [x] Сохранять высоту формы после выхода из аккаунта: кнопка выхода исчезает,
  но остальные элементы страницы не сдвигаются.
- [ ] После ошибки входа оставить понятное сообщение «Неверный логин или пароль»
  и вернуть фокус в поле пароля.
- [ ] Определить политику регистра логина. Сейчас `Tapir19` и `tapir19`
  воспринимаются как разные значения. Если логин должен быть регистронезависимым,
  перед изменением проверить базу на конфликтующие варианты, затем нормализовать
  ввод при регистрации и входе и закрепить это ограничением базы данных.

### OAuth

- [x] Google OAuth работает на production после добавления OAuth-переменных в
  окружение systemd-сервиса.
- [ ] Диагностировать GitHub OAuth. Сейчас после выбора GitHub появляется экран
  NextAuth с сообщением `Try signing in with a different account.` Google при
  тех же условиях работает. Проверить callback URL
  `https://gustaw.ru/api/auth/callback/github`, настройки GitHub OAuth App,
  production credentials и свежие серверные логи во время одной попытки входа.

### Управление учётной записью

- [ ] Добавить безопасную смену пароля для вошедшего пользователя: проверка
  текущего пароля, ввод и подтверждение нового, повторное хеширование и понятный
  результат операции.
- [ ] Отдельно решить, нужен ли сценарий восстановления забытого пароля. Не
  подменять его ручным редактированием хеша в базе.
- [x] Завершить ротацию администраторской учётной записи: новая учётка `Tapir19`
  должна получить роль `ADMIN`, старая `Tapir` — вернуться к роли `USER`.
  Проверить вход и кнопку загрузки под новой учёткой, затем хранить для неё
  отдельный надёжный пароль. Не записывать пароль в репозиторий или документацию.
